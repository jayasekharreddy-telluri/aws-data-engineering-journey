# Task 5 — Partition Pruning Practical

## What We Did

Executed optimized query:

```sql
SELECT order_date,total_revenue
FROM swiggy_gold_db.daily_city_revenue
WHERE city='Bangalore';
```

Executed non-optimized query:

```sql

FROM swiggy_gold_db.daily_city_revenue;
```

Compared:

* 4.09 KB scan
* 65.05 KB scan

## Purpose

Demonstrate partition pruning + columnar optimization.

## Important Learning

* scanned files
* query cost
* execution time

# Task 8 — Create Iceberg Table Using CTAS

## What We Did

Executed:

```sql
CREATE TABLE swiggy_iceberg_db.daily_city_revenue
WITH (
table_type='ICEBERG',
location='s3://swiggy-de-course-jk-20260520/iceberg/daily_city_revenue/',
is_external=false,
format='PARQUET',
write_compression='SNAPPY',
partitioning=ARRAY['city']
)
AS
SELECT *
FROM swiggy_gold_db.daily_city_revenue;
```

## Purpose

Convert normal Parquet table into Iceberg-managed table.

## Important Learning

Iceberg:

* manages metadata
* Parquet stores actual data

# Task 11 — INSERT Into Iceberg Table

## What We Did

Initial INSERT failed due to column mismatch.

Wrong Query:

```sql
INSERT INTO table
VALUES(...)
```

Fixed Query:

```sql
INSERT INTO table
(column1,column2,...)
VALUES(...);
```

## Purpose

Insert new records into Iceberg table.

## Important Learning

Always specify column names during INSERT to avoid TYPE_MISMATCH.

# Task 16 — Recover Deleted Data Using Time Travel

## What We Did

Executed:

```sql

SELECT *
FROM table
FOR VERSION AS OF old_snapshot
WHERE condition;
```

Recovered deleted records.

## Purpose

## Important Learning

Iceberg recovery:

* no backup restore
* no downtime
* metadata-driven
