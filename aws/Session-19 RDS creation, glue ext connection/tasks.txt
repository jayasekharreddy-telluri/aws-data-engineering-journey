# PostgreSQL RDS → Glue → S3 → Athena Practical

## Practical Flow

Local SQL Seed File
↓
PostgreSQL RDS
↓
CloudShell Validation
↓
AWS Secrets Manager
↓
Glue JDBC ETL Job
↓
S3 Silver Layer (Parquet)
↓
Glue Crawler
↓
Athena Querying

---

# Task 1 — Create PostgreSQL RDS Database

## What We Did

* Created PostgreSQL RDS instance
* Enabled public connectivity
* Configured database:

  * DB Name → `swiggy_external`
  * User → `postgres`

## Purpose

Create transactional database source for ETL pipeline.

## Important Learning

RDS acts as OLTP source system in data engineering pipelines.

---

# Task 2 — Configure Security Group

## What We Did

* Allowed inbound rule:

  * Port → `5432`
  * Source → public / Glue access

## Purpose

Allow PostgreSQL connections from CloudShell and Glue.

## Important Learning

Most JDBC failures happen due to networking/security group issues.

# Task 12 — Fix Glue Connection Failure

## What We Did

Skipped Glue Connection UI.

Used:

```python
connection_type="jdbc"
```

directly.

## Purpose

Avoid STS/VPC Glue Connection issues.

## Important Learning

Glue Connections are optional abstractions.

Real-world engineers often use direct JDBC.

# Errors Faced + Fixes

| Error                  | Cause                  | Fix              |
| ---------------------- | ---------------------- | ---------------- |
| Glue Connection failed | STS/VPC issue          | Used direct JDBC |
| sentiment unresolved   | Schema mismatch        | Validated schema |
| S3 PutObject denied    | Missing IAM permission | Added S3 access  |
| JDBC connection issues | Security group         | Opened port 5432 |
